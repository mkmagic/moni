# Moni 1.1 Investments — implementation specification

**Status:** final implementation contract for issue
[#43](https://github.com/mkmagic/moni/issues/43). The decisions in issues
[#35](https://github.com/mkmagic/moni/issues/35) through
[#42](https://github.com/mkmagic/moni/issues/42) are complete. Implement this
specification without starting more research, prototypes, or design branches.

**Reviewed UI:** Variant A in commit
[`f57b0fd`](https://github.com/mkmagic/moni/commit/f57b0fd822d4bd9fbd9d82dde9e84c08c43a5fde).
It is visual evidence only. Rewrite it against the production domain reads; do not
promote its mock data, arithmetic, state switchers, or routes.

**Decision rationale:** [ADR 0008](../adr/0008-investments-use-weekly-account-state-snapshots.md)
and [ADR 0009](../adr/0009-investment-valuation-trusts-broker-observations-and-boi-fx.md).

## 1. Mandatory execution order

1. Work on `feature/investments`. Before changing schema or production code, merge
   `dev` into it. Do not rebase the published branch. Resolve conflicts manually;
   preserve current `dev` behavior, migrations, passkey/credential custody, account
   deletion, and tests. Keep only the investment-specific additions from the feature
   branch. Never resolve this merge with a blanket `ours` or `theirs` choice.
2. Run the four baseline gates after the merge:
   `npm run typecheck && npm run lint && npm run format:check && npm run test`.
   Fix merge regressions before implementing investments.
3. Generate investment migrations after the merge. Do not reuse, renumber, delete,
   or rewrite migrations already on `dev`; accept the next number generated by
   Drizzle.
4. Implement in this order: schema and RLS; connector normalization and promotion;
   valuation; domain reads; API routes; production UI; dashboard integration;
   cleanup; tests and gates.
5. Do not perform new provider, tax, market-data, UX, or architecture research.
   IBKR Flex, Schwab Positions CSV, Tiingo EOD, and BOI SDMX CSV are the decided
   sources. If a fixture exposes an unsupported shape, reject it with a safe error;
   do not broaden scope.

## 2. Product boundary

The screen answers: **What do I own now, and how has its value evolved?**

Moni 1.1 delivers:

- user-triggered IBKR Activity Flex XML refresh;
- user-mediated Schwab Positions CSV import;
- consolidated current investment valuation in ILS;
- native-currency position and cash detail;
- weekly broker-observed portfolio history;
- optional best-effort current estimates from Tiingo EOD closes;
- investment contribution to the dashboard hero's current and historical net worth;
- onboarding, current, empty, stale, mixed-age, refresh-error, reconciliation-
  mismatch, quote-fallback, and generic-instrument states.

Moni 1.1 does **not** deliver Vanguard, Schwab OAuth, an aggregator, a generic CSV
mapper, manual positions, automatic/scheduled refresh, activities, trades, lots,
returns, performance, gains, tax calculations, corporate-action processing,
currency-allocation charts, user-directed instrument merges, MCP tools, or AI
writes. Vanguard in the reviewed prototype is illustrative and must not appear as a
production source until a later specification adds a validated adapter.

## 3. Canonical model

Use the investment terms in `CONTEXT.md` exactly:

- A **connection** is one user-owned source configuration.
- A **sync run** is one atomic attempt to retrieve and promote a connection's
  complete declared coverage.
- An **instrument** is a user-owned canonical asset identity.
- A **position** is a signed quantity of one instrument in one complete account
  snapshot; it is not a trade or lot.
- A **cash balance** is a signed amount by currency in a snapshot; it is not an
  instrument.
- An **investment snapshot** is one source-dated complete account state.
- A **source value** is broker evidence. A **market quote** is public-provider
  evidence. A **valuation** is Moni's calculation under an explicit basis.
- A **portfolio** is a derived consolidated view. Never persist a portfolio row or
  portfolio rollup.
- **Portfolio value history** includes deposits and withdrawals and is never called
  performance, return, gain, or loss.

## 4. Non-negotiable implementation rules

- Every amount, quantity, price, rate, percentage input, and arithmetic intermediate
  is an exact decimal string processed with `decimal.js`. No investment production
  code or fixture may convert a monetary value to a JavaScript `number`. Charts keep
  exact strings for labels/tooltips and may convert only unitless coordinates derived
  from Decimal ratios at the final rendering boundary; a numeric chart coordinate
  must never feed back into valuation logic.
- Encrypt all user financial values, provider account/instrument identifiers,
  symbols, names, account numbers, credentials, and normalized source assertions
  before their first write.
- Every investment-owned table carries `owner_id`, has RLS keyed by
  `app.user_id`, and uses composite owner foreign keys. Public BOI FX rows are the
  only ownerless investment dependency.
- All database access goes through domain functions and `withUser`. Routes, workers,
  React components, and future MCP adapters never query Drizzle directly.
- Reuse the credential and data-key mechanisms present after merging `dev`. Do not
  replace, bypass, or weaken them.
- Tier-0 values remain `Buffer`/`Uint8Array`, cross worker boundaries in the bounded
  binary stdin frame, and are wiped on every completion/failure path. Never put a
  key, Flex token, or query ID in argv, environment variables, JSON, disk, or logs.
- Reads perform no external I/O. Only explicit user-triggered refresh routes may
  contact IBKR, Tiingo, or BOI.
- The feature works fully without a model backend. No investment path imports an
  LLM client or depends on AI output.

## 5. Persistence model

Implement the following schema through Drizzle and generated migrations. Every
ciphertext-bearing row has `version` for AAD and timestamps.

### 5.1 Existing tables

Extend `connections` with a structural mode that distinguishes credentialed fetch
from user-mediated import. Backfill existing connections as credentialed.
`credentials_ct` remains required for existing bank connectors and IBKR, and is null
for Schwab CSV. Domain validation must reject a mode/credential mismatch.
Extend the connector registry with exactly `ibkr_flex` and
`schwab_positions_csv`, both kind `investment`, and make their mode part of the
definition so UI/routes do not maintain a second source list.

Extend `accounts` with nullable `archived_at`. A rich investment account has
`account_type = investment`, `classification = asset`, and null
`current_balance_ct`; its current value is always derived. Existing balance-only
accounts, including any legacy investment-typed row without investment snapshot
detail, continue through the ordinary balance path and are not silently converted.

Extend `account_balance_snapshots` so `native_balance_ct` and `currency` are either
both present or both null. Ordinary snapshots require both. An investment snapshot
has both null and exactly one `investment_snapshot_details` row. Add an investment
source enum value. This table remains the only dated account-observation and
dashboard net-worth seam.

Extend `sync_runs` only with structural investment fields needed for safe status and
counts. `error` remains a sanitized code/message and never contains source values.

### 5.2 New tables

Create these tables with owner/id uniqueness needed by composite foreign keys:

- `instruments`: kind (`stock`, `etf`, `mutual_fund`, `generic`) plus encrypted
  canonical name/symbol labels.
- `instrument_source_mappings`: instrument, provider, structural identifier kind,
  encrypted provider identifier/symbol/name/exchange, and structural currency.
- `investment_snapshot_details`: one-to-one with an account balance snapshot;
  account, connection, sync run, Sunday `week_start`, source as-of value and
  precision (`date` or `timestamp`), encrypted broker account total and its
  currency, reconciliation state, validation version, and structural provenance.
- `investment_snapshot_positions`: snapshot, instrument, encrypted signed quantity,
  quantity unit, position currency, optional encrypted broker price/value and their
  currencies, source valuation as-of, and broker valuation basis.
- `investment_snapshot_cash_balances`: snapshot, currency, and encrypted signed
  amount; unique by snapshot and currency.
- `investment_source_evidence`: accepted connection/sync/account provenance,
  source period/as-of, validation version, row counts, quality codes, and a keyed
  normalized fingerprint. Store no raw payload or financial value here.
- `investment_market_quotes`: user-owned instrument/provider mapping, encrypted
  provider symbol and exact price, plaintext currency/source date/fetched-at,
  split/quality state, and provider.

Required database constraints:

- one active normalized investment snapshot per owner/account/week;
- one normalized position per snapshot/instrument;
- one cash row per snapshot/currency;
- source mappings cannot cross owners;
- snapshot details can reference only an investment account owned by the same user;
- every child owner must match every parent owner;
- ordinary balance snapshots cannot have a half-null amount/currency pair.

Temporal freshness is derived on read from source dates; never persist a `current`
or `stale` boolean that becomes wrong with time.

### 5.3 Identity

Auto-merge source holdings only when equal durable identifiers establish the same
instrument and kind/currency do not conflict. A provider-native identifier matches
only within that provider. Ticker, symbol, and name never establish identity.
Unresolved holdings remain separate and all count in net worth. There is no manual
merge UI in 1.1.

Cash remains separate by currency. Do not create synthetic cash instruments.

## 6. Source adapters and bounded input

Use Zod at the adapter boundary. Parse XML and CSV numeric fields as strings. Configure
the XML parser never to coerce attribute or tag values to numbers. Use a real CSV
parser; do not split lines manually.

Apply these hard bounds before promotion: 10 MiB response/upload, 100 covered
accounts, 10,000 source position rows, 1,000 cash rows, and the existing five-minute
worker timeout. Reject excess as `source_too_large`. Permit at most two transient
network retries after the initial IBKR attempt, within the same timeout. Do not retry
auth, schema, identity, completeness, stale-source, or validation failures.

Extend the child stdin framing with explicit bounded binary segments. IBKR frames
contain the data key plus token/query-ID bytes; Schwab frames contain the data key
plus CSV bytes. Metadata JSON contains only non-sensitive internal IDs and structural
options. The child owns and wipes every decoded byte segment. Do not serialize
credentials or uploaded source bytes into JSON.

### 6.1 IBKR

Use Activity Flex XML through exactly
`https://ndcdyn.interactivebrokers.com/AccountManagement/FlexWebService`.
Allow no other host and reject redirects. Suppress raw URL/error logging because the
Flex token is forced into the query string.

The encrypted Tier-0 credential bundle contains the Flex token and query ID. A sync
requires the existing armed credential window; otherwise return the existing 423
`credential_window_locked` response.

Coverage is every account configured in the query. Stable broker account ID may
discover an account. If any previously known covered account disappears, reject the
whole run. Require account identity/base currency, authoritative source as-of,
complete positions and cash, and a broker total.

### 6.2 Schwab

Accept only the validated Schwab Positions CSV shape. One connection covers one
account. On its first accepted file, bind the encrypted masked account reference and
the user-confirmed valuation currency. Reject future reference or currency mismatch.
Another account requires another connection.

The upload is Tier 1 and uses the active data key, not the credential key. Hold the
file only in bounded memory and pass it to a short-lived import worker without
internet egress. Do not store the raw CSV, filename, path, or raw row.

The validated scope is stocks/ETFs and cash. A row outside a specifically supported
shape becomes `generic` only when the broker supplies stable identity, currency,
quantity, and usable source value. Otherwise reject the complete file. Do not add a
column mapper.

### 6.3 Normalized envelope

Both adapters emit the same in-memory envelope: source; exact declared coverage;
source as-of and precision; and complete accounts containing source account
identity, base currency, positions, cash balances, and broker total. Every numeric
field remains decimal text.

Repeated position rows aggregate only when identity, kind, quantity unit, currency,
valuation basis, and source time agree. Compatible cash rows aggregate by currency.
A conflict rejects all declared coverage.

Zero holdings are valid only when the source explicitly supplies stable account
identity, authoritative as-of, complete empty position/cash sections, and exact zero
broker total. Blank input, no accounts, or omission is failure, not closure.

Raw XML/CSV is parsed in memory and never retained. Persist only encrypted normalized
assertions and structural evidence. The source-control commits containing the POCs
remain the evidence; production does not execute their entry points.

## 7. Atomic refresh and lifecycle

Reuse the existing `sync_runs` lifecycle and polling route. The request creates a
`running` row, spawns one short-lived worker, and returns 202 with the run ID. Browser
close does not cancel work. Keep the existing timeout and lazy orphan repair. Do not
add a scheduler, queue, cancel action, or concurrent-sync redesign.

The worker validates and normalizes all declared coverage before calling one domain
promotion method. That method performs, in one `withUser` transaction:

1. connection/account resolution;
2. instrument mapping;
3. exact source valuation and reconciliation;
4. all covered weekly snapshot, position, cash, and evidence replacement;
5. connection/sync success state.

Any failure rolls back every financial write. Record the sanitized failed run in a
separate guarded transaction. The last accepted snapshots remain readable.

The keyed normalized fingerprint makes an exact repeat a no-op. Within an account's
Sunday-Saturday source week, a newer source time replaces the active normalized
snapshot. Changed content at the same source time is a correction and the later
accepted import wins. Older source time fails as `stale_source`. Ingestion time is
only the equal-source-time correction tie-break. Multi-account IBKR coverage promotes
all accounts or none; Schwab promotes its bound account or none.

Disconnect deletes reusable source access and preserves accounts/snapshots. Disable
disconnect while the connection has a running sync. Archive is a separate explicit
account action that sets `archived_at`, removes the account from current views from
that time onward, and preserves history. Permanent account/user deletion follows the
post-merge `dev` deletion path and cascades all investment-owned rows.

## 8. Valuation and FX

### 8.1 Broker-observed valuation

For each nonzero position, use broker market value when supplied; otherwise compute
exact quantity times broker price. Reject the entire declared coverage if neither is
usable. Sum valued positions and signed cash for Moni's account value. Keep broker
account total separate.

Convert components and broker total to ILS with BOI observations. If their ILS
values differ after each final total is rounded to ILS display precision, persist a
non-blocking reconciliation mismatch. Never modify Moni's sum to equal the broker.

### 8.2 BOI

BOI representative rates are the sole investment FX authority. Fetch bounded SDMX
CSV, parse `OBS_VALUE` and `UNIT_MULT` as decimal text, normalize to ILS per foreign
unit, and cache exact public observations in `fx_rates`. Never use the current-rate
JSON endpoint, broker FX, a later observation, another provider, or `1:1` fallback.

Use the latest BOI observation on or before the relevant date, no more than seven
calendar days old. Fetch missing required dates during the user-triggered source
refresh before promotion. Missing/stale required FX rejects the new source snapshot.
Reads never fetch. BOI corrections update the shared row and may change derived
history. ILS-to-ILS uses exact identity `1` by definition; this is not a missing-rate
fallback.

All consolidated investment values and the dashboard net-worth hero are ILS in
1.1, regardless of profile display currency. Position and cash detail retain native
amounts/currencies. Do not implement a currency toggle or currency-allocation chart.

### 8.3 Tiingo current estimate

For a resolved active USD common stock or ETF on NYSE/Nasdaq, use last accepted exact
quantity times latest usable Tiingo EOD close for the current estimate. Add last-known
cash. Quotes must carry explicit USD currency/source date and be no more than seven
calendar days old. A non-1 split after the quantity observation makes the quote
unusable until a newer broker snapshot supplies post-action quantity.

Missing token, provider-use authorization, mapping, coverage, quote, freshness, or
safe split state falls back per position to broker-observed value. Disclose the
fallback; never fail an accepted broker snapshot. Tiingo changes only current
estimate, never weekly history or reconciliation.

Run quote refresh in a separate short-lived worker with the instance token and no
broker credentials. Restrict egress to `https://api.tiingo.com`, reject redirects,
send the token only in the Authorization header, and log no URL/symbol/value. Do not
call Tiingo more than once per Israeli calendar day for the same refresh action. If
the token or required multi-user provider authorization is absent, make the operation
a local no-op and use broker fallback; do not create a shipping research task.

## 9. Freshness and history

Broker evidence is current when its source observation falls in the present or
immediately preceding Israeli Sunday-Saturday week. Otherwise it is stale. This
week-based rule supersedes ADR 0009's earlier seven-calendar-day broker rule. Tiingo
quote and BOI observation usability retain their seven-calendar-day limits.

Every valuation exposes:

- exact ILS reporting value and applicable native value/currency;
- basis: broker source, Tiingo estimate, or mixed;
- separate source, quote, and FX as-of values;
- freshness: current, stale, or mixed-age;
- quality flags: carried-forward, quote-fallback, reconciliation-mismatch, and
  incomplete-FX as applicable;
- oldest component date and affected-component counts on aggregates; and
- exact reasons on affected account/holding rows.

Weekly history has one point per Israeli week ending Saturday. For each active
account, use that week's accepted complete snapshot; if absent, carry forward the
latest earlier complete account snapshot and mark it stale. Never carry before the
first observation or on/after `archived_at`. A newer complete account snapshot
replaces the carried account state as a whole; never carry individual holdings out
of a newer complete snapshot.

Convert each historical component with BOI FX for its real snapshot date. Group
holding history by canonical instrument; unresolved instruments remain separate.
The chart shows the top seven holdings by average ILS value over the selected range
plus Other. Account grouping shows complete account series. The selected-week detail
returns the complete ungrouped composition and every carried component's real source
date.

Return best-effort `Estimated now` separately from durable weekly points. The UI may
append it as the dotted terminal segment only when it is newer. Never persist it as a
snapshot or include it in historical endpoint change calculations.

Valuation change is endpoint value difference, exact amount and percentage. Label it
**Valuation change** and state **Includes deposits and withdrawals**. Never call it
performance, return, gain, or loss.

## 10. Domain and API reads

Create one internal valuation engine that accepts an RLS-scoped transaction and the
session data key. The following domain methods are the only portfolio read surface:

- `getPortfolioOverview(session)`: exact current ILS total, cash summary, complete
  consolidated holding allocation, connection summaries, account summaries, and
  aggregate valuation metadata.
- `listPortfolioHoldings(session, filters)`: flattened position/cash rows for
  connection/account drill-down.
- `getPortfolioHistory(session, range, groupBy)`: bounded weekly total/composition
  series for `holding` or `account`, plus separate optional estimated-now result.
- `getPortfolioSnapshot(session, week, page)`: complete ungrouped composition used
  for the selected point, page by page.

Expose thin authenticated routes for interactive client reads:

- `GET /api/investments/overview`
- `GET /api/investments/holdings`
- `GET /api/investments/history`
- `GET /api/investments/snapshots/[week]`

Use `POST /api/connections/[id]/sync` for IBKR and for multipart Schwab import; reject
a body/source-mode mismatch. Add `POST /api/investments/quotes/refresh` for the
bounded Tiingo worker and `POST /api/accounts/[id]/archive` for the explicit archive
action. Parse every input with Zod, call only domain methods, and return exact decimal
strings. Server components call domain methods directly rather than loopback HTTP.

Overview totals and consolidated allocation are complete. Holding and selected-week
detail default to 50 rows and cap at 200. Sort by ILS value descending, then stable
row ID. Use opaque cursors bound to a valuation revision; a refresh makes an old
cursor invalid and the client restarts at page one. Return `hasMore` and `nextCursor`.
Support only connection, account, instrument kind, position/cash, freshness, and
valuation-basis filters. Do not implement arbitrary sorts, free-text query language,
or an alternate database read path.

History requires explicit start/end dates. The UI supplies 3M, 6M, 1Y, 3Y, or All;
default to 1Y or all available history when shorter.

MCP is not implemented in 1.1. Preserve future adapter compatibility: tenancy comes
from authenticated call context, never a `userId` argument; decrypted labels are
untrusted data; locked data produces `data_locked`; summary caps at ten holdings plus
exact Other; detail defaults to 25/caps at 50; history defaults to one year/caps at
three years per call. Do not create MCP code in this implementation.

## 11. Production Investments UI

Add a persistent Investments sidebar item. With no investment connection, show the
quiet optional empty state with **Connect brokerage** and **Import statement**.
Moni's other features continue normally.

Rewrite selected Variant A in this order:

1. Hero: current consolidated ILS valuation, cash summary, valuation/freshness
   metadata, Refresh all, Import statement, and consolidated holdings donut. Do not
   show valuation change in the hero.
2. One collapsed card per actual connection, with recognizable local IBKR/Schwab
   marks, ILS valuation, cash, account/position counts, mode, freshness, and per-
   connection action. Expanded cards group accounts and show holding tables.
3. Historical composition graph with Holding/Account switch, presets and draggable
   bounds, valuation change beside the graph, solid broker history, and optional
   dotted Estimated now.

Donut identity is canonical instrument across accounts/connections; cash slices are
separate by currency. Hover shows identity, ILS value, percentage, native
value/currency, and account count. Click pins one holding and cross-highlights its
rows.

Holding columns are holding/symbol, type, quantity, price, native value, ILS value,
account allocation, valuation source, and as-of. Cash rows omit quantity and price.
Clicking a history point opens **As of [week-ending date]** with complete holdings,
accounts, cash, native values, ILS values, and carried-source dates; the rest of the
page stays current.

Refresh all starts fetchable connection syncs, polls them, then triggers the
best-effort quote refresh. It reports Schwab/manual sources that need files; skipped
manual sources are not failures. Per-connection refresh uses the same paths.

State behavior:

- stale source values remain included and mark the relevant row/card and hero;
- one connection failure retains its last accepted snapshot and shows safe inline
  error/retry guidance;
- quote fallback is disclosed in hero metadata and each affected row;
- reconciliation mismatch is visible but non-blocking;
- a generic instrument retains broker identity/value, participates in every total,
  and has no specialized analytics;
- no accepted data means the empty/onboarding state, not a zero-valued populated
  portfolio.

Package the already reviewed IBKR and Schwab favicon images referenced by the
prototype as local static assets. Do not search for alternative marks and make no
runtime remote logo request.

## 12. Dashboard integration

Use the same internal valuation engine inside `getOverview`; do not query investment
tables separately and do not call a portfolio API route.

Change only the dashboard hero contract in this issue:

- current net worth equals ordinary-account current balances converted to ILS with
  usable current FX plus the investment current estimate;
- the hero sparkline becomes genuine month-end net-worth stock values, not monthly
  income minus expenses;
- historical investments use broker weekly snapshots only, never Tiingo;
- for each month end, use the latest account observation on/before that point; carry
  prior observations with mixed-age/stale metadata and obey `archived_at`;
- if a component lacks usable FX, exclude it, mark the total incomplete, and report
  the affected count; never add native units as ILS.

Return a separate `netWorthHistory` and its completeness/freshness metadata from
`getOverview`. Leave the lower dashboard Net Worth stat unchanged; replacing it with
Money Saved is a separate issue. Leave income/expense flow calculations unchanged.

## 13. Logging and audit

Audit only owner-scoped structural facts: connection/account internal IDs, initiating
user ID, sync start/end, source timestamp, result code, safe error code, and row
counts. Never log credentials, query/reference IDs, URLs, filenames, paths, account
references, symbols, names, quantities, prices, values, raw provider errors, or raw
payloads.

IBKR worker egress is limited to the exact Flex host and PostgreSQL. Schwab import
worker has no internet egress. Tiingo worker has only the exact Tiingo API host and
PostgreSQL and receives no broker material. Enforce exact-host and redirect rules in
code and document the corresponding deployment-network restriction; do not build a
new deployment system in this ticket.

## 14. Fixed risks and failure posture

These are accepted constraints, not research tasks:

- IBKR credentials necessarily enter an immutable URL string inside the short-lived
  worker. Exact-host restriction, redirect rejection, log suppression, wiping, and
  immediate process exit bound the residual.
- Provider formats can drift. Version the adapters and fail atomically with a safe
  schema error; never guess a renamed column/tag or accept partial coverage.
- Schwab options, fixed income, mutual funds, shorts, and multi-currency exports are
  unproven. Reject those shapes unless the validated adapter contract already covers
  every required field; do not collect more samples in this implementation.
- Tiingo may be unavailable or unauthorized for a multi-user deployment. Broker
  valuation fallback is the complete product behavior.
- Application host allowlists do not replace deployment egress controls. Document
  the required network policy without expanding this ticket into deployment work.
- Weekly snapshots cannot calculate returns or tax lots. Do not infer missing event
  lineage or add an activity model.

## 15. Tests and acceptance

Use validated redacted fixtures derived from the existing POCs. Do not rerun live
provider probes and do not commit real source data. Playwright is not installed; do
not add a browser-test stack.

Completion requires tests proving:

- migrations apply from current `dev`; every new owned table has RLS, grants,
  owner/id uniqueness, and composite owner FKs;
- user A cannot read, reference, mutate, page into, or aggregate user B's investment
  data through domain or API paths;
- all source numerics remain strings and all arithmetic is exact decimal;
- encryption occurs before first write and ciphertext decrypts only with the correct
  owner key/AAD version;
- Tier-0 framing, wiping, host allowlists, redirect rejection, size/time limits, and
  safe error/log behavior;
- IBKR multi-account and Schwab single-account coverage, zero-state rules, duplicate
  aggregation, identity conflict, missing account, stale source, exact-repeat no-op,
  same-time correction, and full rollback;
- source-value preference, quantity-times-price fallback, missing valuation rejection,
  cash inclusion, BOI conversion, reconciliation mismatch, Tiingo estimate/fallback,
  stale/mixed metadata, and unsupported generic instruments;
- weekly replacement/carry-forward/archive semantics, top-seven-plus-Other grouping,
  complete selected-week detail, pagination/filter bounds, cursor invalidation, and
  no read-time network access;
- dashboard current and month-end stock values, incomplete FX handling, and no
  regression to income/expense flows;
- empty/onboarding and populated server-rendered page paths compile and consume only
  domain/API DTOs.

Before reporting completion run, in order:

1. `npm run typecheck`
2. `npm run lint`
3. `npm run format:check`
4. `npm run test`
5. `npm run build`

All must exit zero. Tests require the repository's live Postgres test setup.

## 16. Required cleanup and final state

After the production screen works, delete both `/prototype/investments` routes, all
losing variants, the prototype switcher/state controls, mock portfolio data, remote
prototype logo wiring, and prototype-only sidebar target. Remove production use of
all live POC entry points; retain their commits as evidence. Remove imports and files
made orphaned by this cleanup.

Update `CONTEXT.md` only if implementation reveals a genuinely new domain term; do
not put schema or code detail there. Reconcile the existing design docs with the
implemented names and remove superseded statements, especially Schwab OAuth,
Vanguard 1.1 support, seven-day broker freshness, raw investment payload retention,
and MCP delivery.

The implementation is complete only when production code contains one RLS-scoped
investment access path, the selected UI is backed entirely by real domain reads, the
dashboard hero uses the shared valuation engine, prototype runtime code is gone, and
every gate above passes.
